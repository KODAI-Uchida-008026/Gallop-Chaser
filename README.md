## プロジェクト概要 <a id="project-overview"></a>

| 項目 | 内容 |
|------|------|
| **ゲームタイトル** | Gallop Chaser |
| **一言で説明すると** | 馬を操作して障害物を飛び越えながら最速タイムを目指すタイムアタックゲーム |
| **ターゲット** | 昔のゲームセンターやメダルゲームのようなカジュアルに遊べるユーザー |
| **制作の目的** | 3D制作の実践　学んだことを実現できる|

| **プレイヤー操作** | A Sと← →で左右移動　Wと↑で加速　Sと↓でジャンプ(長押しで溜める) |

| **失敗条件** | なし　前に自動で進むため溜めるジャンプを意識すれば誰でもクリア可能|
| **特徴・工夫点** | 体力ゲージに影響される加速と溜めるジャンプ |

## 工夫したポイント <a id="highlights"></a>

**工夫①：最速タイムを目指すゲームデザイン**
「クリアすること」ではなく「より速いタイムを目指す」ことをゲームの目的としました。
一度クリアして終わりではなく、プレイヤー自身が操作方法やルートを工夫しながらタイムを縮められる設計にすることで、繰り返し挑戦したくなるゲーム性を意識しました。
また、障害物のひとつにショートカットを配置して、段階的に障害物を高くしたことから、単純に走るだけではなく、プレイヤーの判断や操作によってタイムを短縮できる要素を取り入れました。

**工夫②：体力を利用した加速と溜めジャンプ**
体力ゲージを単なる残り体力の表示ではなく、ゲームプレイに関係する要素として使用しました。
体力を消費することで加速できるようにし、さらにジャンプはボタンを長押しすることで溜められるようにして、溜めた分だけ体力を消費するように設計しました。
これにより、「いつ加速するか」「どのタイミングでジャンプするか」をプレイヤーが判断する必要があり、最速タイムを目指す際の駆け引きにつながるようにしました。

**工夫③：スクリプトの役割分担**
プレイヤー操作や体力管理、UIなどの処理を役割ごとに分け、必要な処理をメソッド単位で整理しました。
スクリプト同士の役割を明確にすることで、処理の修正や機能追加を行いやすくし、保守性と再利用性を意識した設計にしました。

## 苦労した点と解決策 <a id="troubles"></a>

> エラー1つとその解決プロセスを具体的に書くと評価されます。  
> 詳細は [エラーログ](#error-log) も参照してください。

**苦労した点：UIスライダーと体力値の同期**
体力値とUIのスライダーを同期させる処理で、ゲーム開始直後にゲージが急激に減少したり、回復処理がUIに正しく反映されなかったりする問題が発生しました。

**解決策**
体力値の変更処理とUIへの反映処理を見直し、スクリプト間でどのタイミングに値を受け渡しているかを確認しました。
また、UIスライダーなどのオブジェクト参照が正しく設定されていないことで発生する NullReferenceException については、[SerializeField] を使用してInspectorから参照先を設定し、オブジェクト間の参照関係を明確にしました。
その結果、体力値の変化をUIへ正しく反映できるようになりました。

[**詳細はエラーログをご覧ください**](#error-log)
